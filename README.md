# SHARIDEYA — цифровая визитка

Самостоятельный статический проект. Не связан с внутренним приложением учёта и не содержит его исходников или данных.

## Состояние

Сайт: https://vh6djgmg9s-beep.github.io/sharideya-digital-card/

Репозиторий: https://github.com/vh6djgmg9s-beep/sharideya-digital-card

GitHub Pages настроен на main/docs с обязательным HTTPS. Финальные QR, VCF, изображение и NFC-файлы созданы для проверенного адреса. Физическая NFC-метка пока не записана и не проверена.

## Локальный запуск

Требуются Node.js, npm и Microsoft Edge (используется только для генерации PNG и тестов).

```powershell
npm ci
npm run build
npm run dev
```

Открыть http://127.0.0.1:4173. `npm run preview` запускает тот же статический сервер. На хостинге Node.js не нужен: публикуется только `docs/`.

```powershell
npm run lint
npm test
npm audit
```

Playwright запускает установленный Edge в headless-режиме. Результаты и снимки всех ширин — в `artifacts/`. Функции системного обмена и буфера проверяются через контролируемые подмены API. Это не проверка системного окна на физическом iPhone/Android.

## Публикация в отдельный GitHub-репозиторий

1. Войти в GitHub и создать **пустой публичный** репозиторий `sharideya-digital-card`. Не использовать репозиторий учёта. Не включать платный тариф.
2. Из ЭТОЙ папки добавить только новый репозиторий как `origin` и отправить ветку `main`. При необходимости авторизовать обычный Git Credential Manager самостоятельно. Не вставлять токены в файлы или URL репозитория.
3. Settings → Pages → Deploy from a branch → `main` → `/docs` → Save.
4. Дождаться публикации и скопировать фактический HTTPS-адрес из Pages. Включить Enforce HTTPS, если поле доступно.
5. Выполнить (подставив именно выданный Pages адрес):

```powershell
node scripts/finalize-url.mjs https://ФАКТИЧЕСКИЙ-АДРЕС/
```

Скрипт сначала проверяет HTTP 200 и присутствие данных SHARIDEYA по адресу. Только после этого сохраняет URL, собирает QR/NFC/VCF/PNG и запускает тесты.

6. Закоммитить `site-url.txt` и обновлённый `docs/`, отправить в тот же репозиторий и дождаться повторной публикации.
7. Запустить `node scripts/verify-live.mjs`. Он сравнит опубликованные файлы с протестированными локальными байтами и повторно декодирует QR сайта. Только успешная проверка означает завершение публикации.

## Состав

- `src/` — HTML, CSS, JS и локальная SVG-иконка.
- `scripts/` — сборка, сервер предпросмотра, проверки, финализация URL.
- `docs/` — только публичные файлы для GitHub Pages.
- `NFC-INSTRUCTIONS.md` — инструкция записи NFC Tools.
- `TEST-REPORT.md` — результаты и границы проверки.

В `docs/` доступны VCF, QR контакта и изображение визитки. После финализации URL дополнительно доступны `qr-site.png`, `qr-site.svg`, `NFC_URL.txt`, `NFC_URI.ndef`, `NFC_TYPE2_TLV.bin`.

## Безопасность

Нет форм, базы данных, cookies, localStorage, ключей, платных API, трекеров или CDN. Посещение страницы не вызывает внешних запросов: только явное нажатие открывает WhatsApp/Instagram. Внешние вкладки используют `noopener noreferrer`, политика referrer — `no-referrer`. CSP запрещает произвольные скрипты, объекты, формы, внешние ресурсы. GitHub Pages не позволяет задавать произвольные HTTP-заголовки; `frame-ancestors` нельзя надёжно задать через meta, поэтому такая защита здесь не заявлена.

Все npm-зависимости используются только при сборке и тестах, браузер посетителя не загружает npm-код. Lock-файл фиксирует версии. Публиковать только `docs/`, не папки других проектов, `.env`, `node_modules`, `artifacts` или файлы авторизации.
